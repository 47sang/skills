# capture-intent

快速捕获功能意图，产出 `intent.md`——产物链的起点。

## 概述

`intent.md` 是 AI 原生 SDLC 产物链的第一环，用发起人自己的语言描述问题和预期成果。比 `PRODUCT.md` 轻量得多——不需要行为编号、不变量、接口定义，只需要把「为什么要做」和「做好了是什么样」讲清楚。

产物链：`intent.md` → `PRODUCT.md` → `TECH.md` → `plan.md` → 代码 → 评审 → 部署

## 何时使用

- 用户描述了一个新功能或改进想法
- 用户说「新建意图」「写个 intent」「我有个新想法」「要做什么功能」
- 开始一个新的 `specs/NN-xxx/` 规格目录之前

## 工作流程

### 1. 确定目标目录

用 `ask_user_question` 询问用户：

- **选项 A**：指定已有目录（如「specs/14-分镜与镜头视频」）
- **选项 B**：创建新目录

如果选 B，读取 `specs/` 目录，提取最大编号，新目录编号 = 最大编号 + 1。

询问用户功能的简短中文名称（用于目录名后缀），格式：`NN-名称`。

创建目录（如不存在）：`specs/NN-名称/`

### 2. 收集意图信息

通过对话（不必全部用 `ask_user_question`，自然语言交流即可）收集以下信息：

| 维度 | 需要问的 | 示例 |
|------|---------|------|
| **问题** | 遇到了什么痛点？为什么现在要做？ | 「用户每次都要手动复制提示词」 |
| **预期成果** | 做好之后，用户能看到/做到什么？ | 「一键套用预设画风，零配置」 |
| **影响范围** | 涉及哪些现有模块/角色？ | 「资产识别、镜头工作台」 |
| **约束** | 技术/业务/时间/预算约束？ | 「不能影响已有接口、本期不做计费」 |
| **待确认** | 你自己还不确定的点？ | 「要不要支持自定义上传？」 |
| **参照物** | 有没有竞品截图、Figma、参考文档？ | 「参考 XX 竞品的工作台页面」 |

**不需要问的**（留给 PRODUCT.md 阶段）：
- 接口签名、数据结构
- 行为编号、不变量
- 技术选型、架构决策
- 边界 case 的详细枚举

### 3. 创建 intent.md

将收集到的信息写入 `specs/NN-名称/intent.md`，格式如下：

```markdown
# 意图：[功能名称]

> 作者：[用户姓名/代号]。状态：草稿。
> 创建时间：[YYYY-MM-DD]
> 下游产物：[PRODUCT.md]（待生成）

## 问题

[用 1-3 句话描述用户/业务遇到了什么痛点。为什么现在要做这个？]

## 预期成果

[做好之后，用户能看到什么、能做到什么？用用户视角描述，不用技术术语。]

## 受影响的用户和系统

- **用户角色**：[哪些角色会用到？]
- **涉及模块**：[哪些现有模块需要改动或联动？]
- **新增模块**：[是否需要新建模块？]

## 约束

- [技术约束：不能破坏的接口、不能引入的依赖……]
- [业务约束：本期不做什么、预算限制……]
- [时间约束：期望交付时间]

## 参照物

[竞品截图、Figma 链接、参考文档等。没有则写「无」]

## 待确认问题

- [ ] [不确定的点 1]
- [ ] [不确定的点 2]
- [ ] [不确定的点 3]
```

### 4. 写入后确认

创建完成后：

1. 向用户展示 `intent.md` 的完整内容
2. 询问是否需要修改，待确认的问题优先使用`ask_user_question`的方式能够快速地拿到想要的结果，方便你执行下一步的操作
3. 询问是否继续进入下一阶段（写 `PRODUCT.md`），如果要是没有任何需要核实和确认的问题了，可以直接进入到这个阶段

如果用户选择继续，调用 `write-product-spec` 技能，将 `intent.md` 作为输入上下文传递。

## 关键原则

- **轻量**：intent.md 应控制在 1 页以内（30-80 行）。太重了就失去了「快速捕获」的意义。
- **自然语言**：用用户的原话，不要翻译成技术术语。技术术语留给 PRODUCT.md。
- **问题导向**：先讲清楚「为什么」，再讲「做什么」。不讲「怎么做」。
- **不完美也没关系**：待确认问题可以留空。intent.md 是草稿，不是合同。
- **一次对话一个意图**：不要在一个 intent.md 里塞多个不相关的功能。

## 相关技能

- `write-product-spec` — intent.md 确认后的下一步
- `blind-spot-scan` — PRODUCT.md 写完后的盲区扫描
- `write-tech-spec` — TECH.md 技术规格
- `implement-specs` — 规格批准后的实现
- `review-and-iterate` — 实现完成后的审查闭环
